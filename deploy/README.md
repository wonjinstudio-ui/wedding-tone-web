# 배포 키트: 시험 운영 서버 1대 (2026-11-24)

맥에서 터미널로 켜던 4개 프로그램을 서버(Ubuntu 24.04)에서 자동으로 돌게 합니다. 각 프로그램이 하는 일은 [03_web README](../README.md)에 있습니다.

| 서비스 이름 | 프로그램 | 주소(서버 안) |
|---|---|---|
| `wsnap-web` | 웹 화면(Next.js 완성본) | 127.0.0.1:3000 |
| `wsnap-api` | API 서버(Node) | 127.0.0.1:8781 |
| `wsnap-engine` | 엔진 API(파이썬, 미리보기) | 127.0.0.1:8790 |
| `wsnap-worker` | 워커(파이썬, 분석·내보내기) | — |
| `caddy` | HTTPS 앞단. 밖에서는 이것만 보임(80·443) | — |

동작 방식
- 서버가 켜지면 모두 자동으로 켜지고, 하나가 죽으면 3~5초 뒤 다시 켜집니다.
- HTTPS 인증서는 Caddy가 자동으로 받고 갱신합니다.
- 계정·작업 기록 데이터베이스는 매일 새벽 4시에 서버 안에 백업합니다(14일치).

## 시험 운영의 결정: 저장소는 서버 디스크

- 사진과 결과 ZIP은 **R2가 아니라 서버 디스크**(`/srv/wsnap/data/storage`)에 둡니다.
  - 지금까지 페르소나 테스트 7번을 모두 이 방식으로 했습니다.
  - R2 연결 코드는 있지만 실제 R2로 한 번도 돌려 보지 않았습니다.
  - 브라우저가 R2로 바로 올리게 하려면 R2의 CORS 설정과, 이어 올리기에 쓸 R2 목록 읽기 기능이 더 필요합니다.
- 그래서 시험 운영에는 **Cloudflare R2 가입·키가 필요 없습니다.** 도메인만 있으면 됩니다.
- **대가**: 업로드와 ZIP 받기가 서버(유럽)를 거치므로, 한국에서 1GB를 올리는 데 몇 분 걸릴 수 있습니다. 실제 시간은 서버를 띄운 날 잽니다.
- **디스크**: 결혼식당 약 3.5GB이고 14일 뒤 지워집니다. 80GB 서버면 동시에 약 20건까지 들어갑니다.
  - 1,532장 결혼식 실측(2026-11-25): 올린 사진 0.86GB + 작업 1.4GB
  - 작업 1.4GB의 내역: 올린 사진 복사본 0.86GB, 미리보기 0.44GB, 사람 분리 0.14GB(처리 단계 '사람 분리'에서 저장)
  - 결과 ZIP은 약 1.2GB로 추정했습니다(아직 실측 전).
- R2로 옮기는 일은 유료 출시 전 단계에서 따로 합니다(아래 '나중에').

## 처음 한 번 (대표님 + 저)

1. **대표님**: Hetzner에서 서버 만들기
   - Cloud → 서버 추가
   - 위치: Falkenstein·Nuremberg(독일) 또는 Helsinki(핀란드)
   - 이미지: **Ubuntu 24.04**
   - 종류: **CAX21**(ARM, 4 vCPU, 8GB, 80GB)
   - **SSH 키**: 제가 이 맥에서 만든 공개 키를 붙여 넣기
   - 백업: 켜기 권장(월 서버값의 20%, 서버 전체를 매일 복사)
2. **대표님**: 도메인 DNS에 `A 레코드` 추가 → 이름은 원하는 주소(예: `app`), 값은 서버 IP
   - Cloudflare에서 산 도메인이면 **프록시(주황 구름)는 끄고** 'DNS only'로 둡니다. 1GB 업로드가 Cloudflare 무료 요금제의 요청 크기 제한(100MB)에 걸리지 않게 하려는 것입니다.
3. **저**: 맥에서

   ```bash
   bash "03_web/deploy/push.sh" root@서버IP 도메인
   ```

   다음을 한 번에 합니다.
   - 코드와 모델 올리기
   - 서버 준비(`server-setup.sh`)
   - 설치와 켜기(`install.sh`)
   - 점검(`check.sh`)
4. **저**: 첫 결혼식(니콘·소니 샘플 + 캐논 일부)으로 처리 시간과 미리보기 속도를 재고, [22번 문서](../../22_운영%20비용%20정리.md)의 추정을 실측으로 바꿉니다.

## 코드를 고친 뒤 다시 올리기

```bash
bash "03_web/deploy/push.sh" root@서버IP
```

- 고객 사진·작업 폴더(`02_prototype/work`), 개발 데이터(`devdata`), 가짜 사진(`devfake`)은 **올리지 않습니다.**
- 작가 필터는 데이터 폴더에 있어 다시 올려도 지워지지 않습니다.
- 워커가 내보내기 중이면 그 작업을 끝낸 뒤에 새 코드로 바뀝니다.

## 서버 안의 위치

| 위치 | 무엇 |
|---|---|
| `/etc/wsnap/wsnap.env` | **설정과 비밀 값.** 엔진 키는 처음에 자동으로 만듦. 바꾼 뒤 `sudo systemctl restart wsnap-api wsnap-engine wsnap-worker wsnap-web` |
| `/srv/wsnap/app/engine`, `/srv/wsnap/app/web` | 코드(맥에서 올림) |
| `/srv/wsnap/data` | 데이터베이스(`app.sqlite`, `jobs.sqlite`), 사진·결과(`storage`), 작업(`work`), 작가 필터(`filters`) |
| `/srv/wsnap/backups` | 매일 데이터베이스 백업 |
| `/var/log/caddy/wsnap.log` | 접속 기록 |

## 시험 운영 설정에서 알아 둘 것(`wsnap.env`)

| 설정 | 값 | 뜻 |
|---|---|---|
| `FREE_WEDDINGS=100` | 무료 결혼식 100건 | 시험 운영은 결제 화면이 안 뜨게. 유료로 바꿀 때 1로 |
| `DEV_PAYMENTS=0` | | 개발용 '결제 완료' 버튼 끔 |
| `TRUST_PROXY=1` | | Caddy 뒤에서 접속한 사람의 실제 IP로 로그인 시도 횟수를 셈 |
| `WSNAP_MEM_MAX=40` | | 엔진 API가 메모리에 들고 있는 사진 수(8GB 서버용) |

## 나중에(유료 출시 전)

- **R2로 옮기기**: 버킷 CORS, 이어 올리기용 R2 목록 읽기, 워커의 `boto3` 설치, `--storage r2://버킷`. 실제 R2로 시험한 뒤 바꿉니다.
- **PostgreSQL**: 서버를 여러 대로 늘릴 때.
- **구글·카카오 로그인 키**: `wsnap.env`에 넣고 `wsnap-api`를 다시 켜면 됩니다.

## 이 맥에서 확인한 것 / 아직 못 한 것

**확인한 것**
- 스크립트 5개 문법 검사
- 웹 화면 완성본 빌드(화면 16개)
- 완성본으로 로그인 → 목록 → 기준 컷 미리보기·슬라이더 동작
- 서버 시험 10개 통과

**아직 못 한 것(서버를 띄운 날 확인)**
- Ubuntu에서의 실제 설치: Node 24·uv·Caddy 설치 명령, 리눅스 ARM용 파이썬 패키지 설치, MediaPipe가 필요로 하는 시스템 라이브러리
- HTTPS 인증서 발급
- 서비스 자동 실행
- 한국↔유럽 업로드 속도

처음 배포 때 막히는 곳이 있으면 그 자리에서 고치고 이 문서에 적습니다.
